# PLANCK additive cooperation API revision 2

The source implements the plain-C table in [planck_synergy.h](../include/planck_synergy.h). Request revision `2` through the existing SKSE PLANCK message's `GetApiFunction`, at PostPostLoad or later. Check the returned table's `version`, `size` and `capabilities` before using it. Revision 001, its vtable and its extended hit event are unchanged. This extension is development source, not a qualified native release.

## Ownership and callback lifetime

Register a unique UTF-8 client ID. Every endpoint, actor-policy lease, geometry request and callback registration belongs to that client. Another client cannot release or query its resources. Tokens are process-local, monotonic and never serialized. RegisterClient zeroes its output on failure. Resource limits return `LIMIT`: 64 clients, 512 resources, 512 published actors, 256 bodies per actor, 16 hit policy callbacks and 256 retained hit snapshots.

`Unsubscribe` removes both event subscriptions and hit policy registrations. `ReleaseClient` closes the client and stops new callbacks before testing drainage. Both are nonblocking: `BUSY` means a callback is in flight; retry after it returns. Only `OK` confirms it is safe to free callback code/context. A callback can remove itself, but gets `BUSY` until it has returned. A closing client cannot acquire new resources. There is no background waiter, blocking unload or implicit DLL pin. `ReleaseLease` releases endpoints, actor policies and retained geometry request records. Geometry changes already applied to a live body are persistent until another proposal or body replacement; releasing a completed request is not a shape rollback. A native replacement already admitted to Havok cannot be cancelled or discarded before adoption/lifetime invalidation; cancellation, release and client closure return `BUSY` during that interval.

All public entry points contain C++ implementation exceptions. Callbacks must not throw or block. A throwing observer is retired; a throwing, malformed or slow hit policy is retired and vetoes that hit. Copy operations and nonblocking resource removal are allowed from callbacks. Registration, endpoint acquisition and new actor-policy requests return `REENTRANT` there. No callback may change live engine objects, inventory, damage or ragdolls. The copied decision is the only writable hit-policy output. Consumer teardown must drain every provider that still calls its code.

## Samples, generations and phases

Set every input/output record's `size` to `sizeof(record)` and zero reserved fields. The ABI fixes packing to 8 and uses fixed-width integer fields, POD records and caller buffers; it transfers no STL values or allocated memory. Vector units are meters, axes are the game's Havok axes. Capsule endpoints and endpoint attachment points are body-local; position/xyzw rotation map body-local to Havok world space. There is no player hand remapping: hit hand is right=0, left=1, unavailable=2.

`CopyActorPhysics` atomically copies actor metadata and its complete body array. On `BUFFER`, only required capacity is returned; retry to obtain one coherent sample. All copied bodies share the returned sample ID. Samples are observations from the main actor maintenance pass, not a promise that a cached pose stays live. Native publication acquires graph then world ownership and commits the registry copy before releasing either lock; publication observers dispatch afterward. The stored numerical native identities are comparison keys, never dereferenced by an executor. Samples include main-frame count, the separate prephysics-tick count, and PLANCK's frame time in seconds. Active ragdolls only are published; absence is `NOT_FOUND`, not an assertion that an arbitrary NPC has no collision or no body.

For a new pose reader, `CopyActorPhysics` returns the pose, actor/body generations, and `observedAtNs` in one call. Check the returned actor record size before reading the tail. The timestamp uses QPC-based monotonic nanoseconds (MSVC steady clock) at body capture, so Body Slots can compare it to a HIGGS palm observation. Zero means the source clock is unavailable. The field `timeSeconds` retains PLANCK's elapsed frame clock. Clients built with the 72-byte actor record still receive exactly that prefix. They can use `CopyActorSampleTime` when the table size and `PLANCK_CAP_SAMPLE_TIME` bit support it, and retry a stale sample.

An endpoint contains an owned lease, actor handle, epoch, actor generation, body generation/index and copied local point. Acquire validates the exact publication; Validate checks ownership and current generations. Actor/model/ragdoll/body-list replacement, deactivation/unload, physical entity removal/deletion and world/load reset invalidate dependent endpoints and actor-policy leases. Invalidation callbacks name the old actor reference. Actor and body generation tokens never recycle within the process. A geometry revision is separate from body generation.

SKSE PreLoadGame suspends API publication, advances its epoch and cancels queued hit work; PostLoadGame (including failure) resumes publication. A successful load, NewGame or world replacement also resets physical tracking. Client identities and subscriptions survive reset. Global hit registrations survive; actor-scoped hit registrations retain their exact old reference and cannot attach to a replacement. Release retired resources explicitly. A reset cancels outstanding geometry request records and advances the epoch; it never resolves an old native address against a replacement body.

| Operation/callback | Thread and phase contract |
|---|---|
| Public table calls | Any thread; copied registry access is mutex protected |
| Actor publication/events | Main actor maintenance, after releasing graph/world locks |
| Candidate/policy/terminal-hit callbacks | Synchronous committing thread; melee task thread or clutter/contact thread; may already hold world ownership |
| Entity invalidation/events | Synchronous physics removal/deletion thread; may hold world lock |
| Load/reset events | The engine's lifecycle thread |

Event and hit records include a provider-local process thread ID and phase. These IDs are descriptive, not OS handles or permission to mutate the engine. Callbacks run outside the API registry mutex, with no guarantee that an engine lock is absent. Events pass a callback-lifetime copied record. Hit event `subject` is its snapshot ID; query `CopyHitSnapshot` before retention eviction/reset. Actor events require a fresh actor copy. The ordinary API returns validated copied descriptors. A separate opt-in native-provider bridge described below supplies a scoped live-body visit; the endpoint itself is not a physical constraint. HIGGS remains responsible for the constraint, its retained references and immediate invalidation response.

## Hit interpretation and commitment

`RequestActorPolicy` returns an immediate owned restriction lease for the exact actor generation. Suppress-hits is an OR across matching leases. Clutter damage scales use the smallest requested scale in [0,1]. Releasing one lease never restores or edits global PLANCK settings. These are commutative restrictions; registrations do not compete for an exclusive user action and do not use registration-time priority.

The native melee task calls BeginHit before swing/hit side effects. It refuses stale queued work and replacement hit nodes, and checks the node/reset fence again immediately before `HitActor`. Clutter calls BeginHit after populating HitData and before `Actor_GetHit`, cooldown and hitting-object damage. A veto skips those commitment side effects. The existing collision-detection/cooldown admission path before the melee task is unchanged; policy does not undo already observed contact.

Candidate observers cannot change the decision. Matching policies receive copied pending data, with veto-wins and minimum clutter scale. Callbacks must return within 1 ms; a measured overrun disables that policy and vetoes the current hit. The whole policy dispatch budget is 2 ms and at most 16 callbacks. These are cooperative deadlines: native C code cannot safely preempt a callback that never returns. Melee supports veto only (`proposedDamage=-1`); its engine damage is not yet known. Clutter supplies proposed engine damage, and its effective damage fields are scaled before commitment. No claim is made that the post-mitigation health loss equals this proposal. Numeric melee damage rewriting is not advertised.

BeginHit snapshots remain pending until the actual native commitment or early-return cancellation calls FinishHit. A denied hit is already terminal. FinishHit publishes exactly one immutable allowed/cancelled result and cannot turn a denial into an allowed result. Target invalidation during policy processing stores a terminal cancelled snapshot and emits one terminal event; FinishHit cannot recommit it. A reset that already evicted the snapshot does not recreate an old-epoch record or emit a hit event referring to that evicted snapshot. `PLANCK_HIT_FINALIZED` (also named `PLANCK_HIT_COMMITTED` for earlier consumers) reports the final processing outcome. Check the snapshot: allowed means the native hit handler ran, denied means a policy veto, and cancelled means the hit did not reach the handler. Health loss is not measured. This API covers PLANCK player melee and PLANCK clutter physics damage, not every ordinary engine/spell/projectile hit.

When all 256 retained hits are pending, the next hit still runs matching policies. Its policy callback receives a snapshot with `hitId=0`, valid only during that call. No candidate or final event is issued for that unrecorded hit. Reading hit history can never veto a hit.

## PPB capsule geometry adoption

`PLANCK_CAP_CAPSULE_GEOMETRY` is advertised when the native geometry adapter is installed at plugin startup. `RequestActorGeometry` validates the exact world/actor/body generations and expected geometry revision, finite body-local capsule endpoints bounded to +/-100 meters per component, and radius in (0,10] meters. Only a direct capsule with an independent engine-clonable wrapper is supported. Compound and noncapsule shapes return `UNSUPPORTED`; the API does not reinterpret them as capsules. A competing pending proposal for the same body returns `CONFLICT`. Its owner can query the copied accepted/completed/rejected/cancelled result and release the retained request with `ReleaseLease`.

Queued requests contain copied identities and geometry, never an engine pointer. The existing actor-maintenance pass acquires graph then world write ownership, captures current live ragdoll bodies and publishes that sample before processing proposals against that exact capture. A separate native gate serializes physical admission against reset and lifetime invalidation; no registry mutex is held while the engine applies geometry. The native adapter uses the existing engine `NiObject_Clone` binding to clone the shape wrapper. It verifies that both wrapper and native capsule are independent, edits the clone, and asks the rigid body's shape setter to refresh its broadphase/agent cache. Authored/shared capsules are never changed. Mass and inertia are preserved; this fitting operation is not a mass-policy service.

A critical-operation lock postpones admission. If Havok itself defers a replacement, the request remains accepted and cannot be cancelled, released or dropped by client closure until actual adoption or body invalidation. Completion requires observing that the exact cloned capsule is installed; it does not mean only that a setter was called. Geometry revision advances once. Shape/result observers dispatch after graph/world locks are released. The private adapter retains each installed wrapper and native body (at most 512 live shape records) until that entity is removed. Removal clears the wrapper back-pointer before retiring the wrapper, so a separately retained native body cannot refer to freed wrapper memory. Reset cancels API work but does not prematurely drop wrappers still referenced by live or deferred native bodies; engine entity removal performs their final retirement.

## Native endpoint bridge for HIGGS

Request `GetApiFunction(3)` to obtain the version-1 [PlanckPhysicalInteropAPI](../include/planck_physical_interop.h). This is a deliberately separate native-provider interface; the revision-2 gameplay table still transfers only copied data. An executor registers its own PLANCK client and independently acquires an endpoint from the copied body reference/local point supplied by its gameplay provider. Another client's lease is never silently adopted.

`WithAttachmentEndpoint` is synchronous. It is available only on the thread observed by PLANCK's actor-maintenance pass; before that pass or from another thread it returns `BUSY`. The caller must invoke it at a main maintenance boundary before acquiring any engine/world lock. The native resolver retains the actor and world, acquires graph then world write ownership, freshly resolves the same live body index, and rechecks actor/model/body/lineage generations before invoking the visitor. A stale endpoint never exposes a native pointer. The callback receives `PlanckNativeEndpoint`: borrowed `hkpRigidBody*` and `hkpWorld*` encoded as 64-bit addresses, copied pose, exact endpoint and observed sample/geometry revision. It runs outside the API registry mutex while the native lifetime gate and graph/world ownership remain held.

This privileged callback is for compatible HIGGS/Havok adapters. Engine addresses are valid only until it returns: no caching, freeing, serialization or later dereference. HIGGS may create its own constraint or acquire its own qualified native reference in that visit, and must retire dependent work when `ENDPOINT_INVALIDATED` or reset arrives. A retained reference keeps memory alive, not membership in a world. No inventory/gameplay calls, waiting, further graph/world acquisitions or recursive bridge calls are permitted. The visitor must not throw. Endpoint/client removal returns `BUSY` until a currently admitted visitor returns; only successful drainage permits unloading its code/context.

## Verification and remaining work

The separate [compound-capsule geometry API](compound-geometry-api.md), discovered with `GetApiFunction(5)`, adds coherent child snapshots and atomic existing-list fitting requests. It complements direct capsule adoption without changing the revision-2 table. It supports bounded capsule-only lists with independently cloned wrappers; arbitrary new topology or a mixed-shape editor is not advertised.

The separate [version-1 scoped drive policy](drive-api.md), discovered with `GetApiFunction(4)`, adds actor-generation pivot restrictions, three selected controller gains, body-specific weight multipliers and copied drive observations. It preserves the tables above and keeps PLANCK as the actual native writer. Full PPB pose-conforming and arbitrary joint/controller edits remain outside that bounded contract.

The [offline fixtures and runner](https://github.com/Vhodnoylogin/activeragdoll/blob/ab6291e949d1b00fcb3ebac8ce7d17d983445e1e/tests/run_synergy_tests.py) are maintained alongside the provider prototype.

Actor sampling and drive observation start with the first registered client. Releasing the last client drops its copies and stops sampling. A melee task queued before registration uses its original path. [Interaction framework proposal](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/concept-en.md).
